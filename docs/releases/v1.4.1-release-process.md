# MUG v1.4.1 Release Process

This process keeps release publication explicit. The helper script is safe by default and does not commit, tag, push or publish unless the matching flags are passed with `--yes`.

## Requirements

- Python virtual environment with project dependencies installed.
- GitHub CLI authenticated with access to `pancotto/MUG`.
- Inno Setup CLI available at:

```powershell
C:\Program Files (x86)\Inno Setup 6\ISCC.exe
```

Check GitHub CLI authentication:

```powershell
gh auth status
```

## Manual Validation Flow

Run these before publishing a release:

```powershell
.venv\Scripts\python.exe -m compileall app.py core ui tests benchmarks scripts -q
.venv\Scripts\python.exe -m pytest tests -q --basetemp .tmp_pytest -p no:cacheprovider
.venv\Scripts\python.exe benchmarks\benchmark_release.py --version v1.4.1
.venv\Scripts\python.exe scripts\validate_release.py --version v1.4.1
.venv\Scripts\python.exe -c "import app; import ui.graph_page; import ui.input_page; import core.pdf_exporter; import core.time_filter; import core.graph_builder; import core.update_checker; print('smoke imports ok')"
```

Build and manually validate the executable:

```powershell
cmd /c build_exe.bat
```

Manual executable checks:

- App opens normally.
- Version is correct.
- Icon is correct.
- Chromium/Kaleido export paths work.
- PDF export works.
- Image export works.
- ETL opens supported files.

Build the installer only after the executable passes manual validation:

```powershell
& "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" installer_mug.iss
.venv\Scripts\python.exe scripts\validate_release.py --version v1.4.1
```

## Dry-Run Release Flow

Use the release orchestrator to run non-publishing checks and print release notes:

```powershell
.venv\Scripts\python.exe scripts\publish_release.py --version v1.4.1
```

For a faster metadata/test-only rehearsal, skip the benchmark:

```powershell
.venv\Scripts\python.exe scripts\publish_release.py --version v1.4.1 --skip-benchmark
```

The dry-run flow does not commit, tag, push or publish.

## Build-Oriented Flow

Run the executable and installer build steps from the orchestrator:

```powershell
.venv\Scripts\python.exe scripts\publish_release.py --version v1.4.1 --build --installer
```

If Inno Setup is not in the standard location, pass the path explicitly:

```powershell
.venv\Scripts\python.exe scripts\publish_release.py --version v1.4.1 --installer --inno "C:\Program Files (x86)\Inno Setup 6\ISCC.exe"
```

## Full Release Flow

After reviewing staged files, release publication steps require explicit flags and `--yes`:

```powershell
.venv\Scripts\python.exe scripts\publish_release.py --version v1.4.1 --commit --tag --push --publish-github --yes
```

The script refuses commit/tag/push/publish actions without `--yes`.

## Commit Safety

Do not stage generated artifacts:

- `build/`
- `dist/`
- `installer/*.exe`
- `__pycache__/`
- `.pytest_cache/`
- `.tmp_pytest/`
- `docs/benchmarks/artifacts/`

Use explicit staging paths instead of `git add .`.
