# MUG v1.3.8

## Highlights

- ETL optimization for faster TXT measurement loading.
- Graph caching for already generated graph views.
- Conservative parallel daily PDF export.
- Cooperative export cancellation for current and custom exports.
- Shift-click interval selection in detected-day tables.
- Drag interval selection improvements.
- Export filename standardization with timestamp and revision tokens.
- Export collision protection for existing or locked PDF files.
- Standardized export completion, cancellation and error dialogs.
- Automated benchmark infrastructure for release validation.

## Performance

- ETL: 6.104s -> approximately 1.95s.
- Daily PDF export: 11.218s -> approximately 7.26s.
- Graph generation remained stable.

Benchmark reference:

- Startup subprocess: 1.375s.
- App import: 1.196s.
- ETL: 1.946s.
- Initial graph generation: 1.432s.
- Current measurement PDF export: 1.974s.
- Custom single PDF export: 1.772s.
- Custom daily PDF export: 7.258s for seven PDFs using one selected graph.

## Improvements

- Renamed the standard active-interval export action to Exportar Medicao Atual.
- Improved SELECAO day-range preparation with drag and Shift-click workflows.
- Kept active interval application explicit: prepared ranges do not refresh graphs until applied.
- Embedded custom export interval controls now follow the same date/time preparation pattern as SELECAO.
- Added current-measurement export cancellation using the same cooperative cancellation path as custom export.
- Standardized all generated PDF filenames using:
  - `GR - EMPRESA - YYYYMMDD-HHMMSS - REV00.pdf`
  - duplicate-safe suffixes such as `(2)` and `(3)`.
- Precomputed unique output paths before parallel daily exports to avoid worker filename races.
- Added retry behavior when a target PDF is already locked or unavailable.

## Known Limitations

- PDF export time still scales with selected graph count because Plotly/Kaleido renders each selected graph.
- RSS memory metrics require optional `psutil`; the release benchmark used `tracemalloc` fallback in this environment.
- XLS import requires validation with a real `.xls` sample when available.
